- AI tạo lại chi tiết vật thể.


======================================================================
3. ĐỊNH NGHĨA “PIXEL ACCURATE”
======================================================================

Cần tách hai khái niệm.


3.1 Độ trung thực RGB

Đây là yêu cầu có thể kiểm soát tuyệt đối.

Trong chế độ SOURCE_FAITHFUL:

    output.width == input.width
    output.height == input.height

Sau khi decode về cùng orientation:

    output_rgba[:, :, 0:3] == source_rgb

Nếu khác dù một pixel RGB ngoài chủ đích:

    TEST FAIL


3.2 Độ chính xác foreground/background

Không có model AI nào có thể bảo đảm mọi pixel đều đúng trong mọi loại ảnh.

Các trường hợp khó:

- foreground và background cùng màu;
- vật thể trắng trên nền trắng;
- vật thể đen trên nền đen;
- motion blur;
- kính trong;
- nhựa trong;
- vật liệu bán trong suốt;
- reflection;
- tóc;
- lông;
- dây nhỏ;
- soft shadow;
- smoke;
- out-of-focus;
- background nhìn xuyên vật trong suốt.

Vì vậy hệ thống phải kết hợp:

- segmentation;
- matting;
- topology validation;
- uncertainty detection;
- high-resolution edge refinement;
- manual correction.

Phải phân biệt:

    AUTO RESULT

và:

    VERIFIED RESULT

VERIFIED RESULT chỉ được coi là hoàn tất khi user đã kiểm tra hoặc sửa vùng AI không chắc chắn.

4. MODEL STACK CHO V1
======================================================================

Model cốt lõi:

1. BiRefNet_HR-matting
2. SAM 2.1 Base+
3. ViTMatte-B

Không thêm model thứ tư mặc định nếu benchmark chưa chứng minh rõ lợi ích.


4.1 BiRefNet_HR-matting

Vai trò:

- model foreground chính;
- tạo alpha proposal;
- automatic cutout ban đầu;
- xác định silhouette chính;
- xác định confidence ban đầu.

Đây là model chạy đầu tiên trong pipeline mặc định.

Yêu cầu:

- hỗ trợ adaptive resolution;
- hỗ trợ FP16 nếu ổn định;
- output không được mặc định coi là final alpha native-resolution.


4.2 SAM 2.1 Base+

Vai trò:

- object selection;
- positive point;
- negative point;
- bounding box;
- topology validation;
- interactive correction;
- xác định đúng vùng vật thể;
- bảo toàn lỗ và khe.

Ví dụ:

- lỗ trong quai cốc;
- khoảng trống giữa các ngón tay;
- ống hút sát nắp;
- dây;
- vòng;
- vật thể mảnh;
- nhiều object chạm nhau.

SAM2 không được thay toàn bộ final alpha nếu không cần.


4.3 ViTMatte-B

Vai trò:

- alpha matting;
- refine đường biên;
- tóc;
- lông;
- anti-alias;
- cạnh mảnh;
- vùng bán trong suốt.

ViTMatte-B mặc định chỉ chạy trên ROI vùng biên.

Không chạy toàn ảnh native-resolution nếu benchmark chưa chứng minh cần thiết.


======================================================================
5. CHIẾN LƯỢC NHIỀU MODEL
======================================================================

Không được triển khai kiểu:

    final = (maskA + maskB + maskC) / 3

Không average mask mù quáng.

Vai trò riêng:

    BiRefNet -> foreground / alpha proposal
    SAM2     -> object membership / topology
    ViTMatte -> boundary alpha refinement

Hệ thống phải xác định:

- confident foreground;
- confident background;
- uncertain region;
- topology conflict;
- boundary region.

Chỉ vùng khó mới chạy model thứ hai hoặc thứ ba.

Mục tiêu:

- giảm VRAM;
- giảm thời gian;
- tránh model này phá output tốt của model khác.

======================================================================
7. NATIVE-RESOLUTION LÀ YÊU CẦU BẮT BUỘC
======================================================================

Output phải giữ nguyên kích thước ảnh gốc nếu user không yêu cầu resize.

Ví dụ:

Input:
    5000 x 5000

Có thể chạy BiRefNet ở:

    1536 x 1536

Nhưng không được:

    1536 mask
    -> upscale 5000
    -> export trực tiếp

Phải làm:

    inference proxy
    -> approximate mask
    -> approximate edge
    -> map edge về original coordinate
    -> crop ROI từ ảnh ORIGINAL
    -> high-resolution local refinement
    -> ghi alpha trực tiếp vào alpha canvas native-resolution

Vùng chắc chắn foreground:

    alpha = 1.0

Vùng chắc chắn background:

    alpha = 0.0

Chỉ vùng boundary và vùng chưa chắc chắn cần xử lý nặng.

======================================================================

Trimap gồm:

- unknown;
- definite background.

Unknown width phải adaptive.

Gợi ý:

Ảnh nhỏ:
    4-12 px

Ảnh vừa:
    8-24 px

Ảnh lớn:
    16-48 px

Hair/glass:
    có thể rộng hơn.

Không dùng một width cố định cho mọi ảnh.


======================================================================
11. ROI-BASED EDGE REFINEMENT
======================================================================

Không refine toàn ảnh nếu không cần.

Pipeline:

    coarse boundary
    -> detect uncertain region
    -> merge nearby regions
    -> thêm context margin
    -> crop ROI
    -> tile nếu ROI lớn
    -> ViTMatte-B
    -> weighted alpha merge
    -> write alpha về native canvas

ROI mặc định:

    512 x 512

ROI lớn:

    768 x 768

Overlap:

    96-128 px

Không blend RGB.

Chỉ alpha được weighted merge.

12. TỐI ƯU WINDOWS + GTX 1660 SUPER 6GB
======================================================================

12.1 Backend

Ưu tiên:

    CUDA

Fallback:

    CPU


12.2 Giới hạn VRAM

VRAM vật lý:

    6 GB

Không sử dụng toàn bộ.

Soft limit:

    khoảng 5.0-5.2 GB

Phần còn lại dành cho:

- CUDA context;
- Windows;
- tensor tạm;
- image buffers;
- fragmentation.


12.3 Chạy model tuần tự

Không load đồng thời ba model lớn.

Luồng:

    load model
    -> infer
    -> lưu alpha/mask vào RAM
    -> unload
    -> clear cache
    -> load model tiếp theo

Ví dụ:

    load BiRefNet
    infer
    save result
    unload

    nếu cần:
        load SAM2
        infer
        unload

    nếu cần:
        load ViTMatte
        infer ROI
        unload


12.4 BiRefNet adaptive resolution

Thứ tự thử:

    1536
    1280
    1024

Startup benchmark có thể thử:

    1024
    1280
    1536
    1792
    2048

Không giả định 2048 sẽ chạy ổn.

Lưu max stable resolution.


12.5 Precision

Benchmark:

- FP16
- FP32

Ưu tiên FP16 nếu:

- không làm giảm chất lượng;
- model chạy ổn;
- tiết kiệm VRAM.

GTX 1660 Super không có Tensor Core RTX.

Do đó không được giả định FP16 luôn nhanh hơn đáng kể.

Lợi ích chính có thể là giảm VRAM.


12.6 CUDA OOM recovery

Khi OOM:

1. dừng inference hiện tại;
2. xóa tensor tạm;
3. unload model không dùng;
4. torch.cuda.empty_cache();
5. giảm resolution;
6. retry;
7. nếu vẫn fail -> CPU fallback.

App không được crash.

13. TỐI ƯU MACBOOK PRO M4
======================================================================

13.1 Backend

Ưu tiên:

    PyTorch MPS

Tức Metal / Metal Performance Shaders.

Fallback:

    CPU

Không để code chung phụ thuộc CUDA.


13.2 Device detection

Khi startup:

    nếu CUDA available:
        device = CUDA
    elif MPS available:
        device = MPS
    else:
        device = CPU

Phải dùng DeviceManager.


13.3 Unified Memory

Apple Silicon dùng unified memory.

Không coi đây là VRAM tách biệt.

Không hard-code:

    M4 = 6GB VRAM

Phải phát hiện:

- total system memory;
- available memory;
- memory pressure nếu khả thi;
- model memory estimate;
- safe inference resolution.

Phải chừa bộ nhớ cho:

- macOS;
- frontend;
- source image;
- model;
- temporary tensors;
- alpha buffers.


13.4 MPS fallback

Một số PyTorch op có thể chưa hỗ trợ MPS đầy đủ.

Hỗ trợ:

    PYTORCH_ENABLE_MPS_FALLBACK=1

Yêu cầu:

- unsupported operation có thể fallback CPU;
- ghi log rõ;
- không crash toàn pipeline;
- benchmark quality MPS riêng.


13.5 Precision trên M4

Benchmark:

- FP16
- BF16 nếu model/backend hỗ trợ ổn định
- FP32 fallback

Không ép cùng dtype cho tất cả model.

Mỗi engine có profile riêng.

Ví dụ:

    BiRefNet:
        MPS + FP16 nếu ổn

    SAM2:
        dtype đã test

    ViTMatte:
        dtype đã test

Nếu model nào lỗi:

    fallback riêng model đó về CPU


13.6 Adaptive resolution trên M4

Không hard-code.

Startup benchmark:

    1024
    1280
    1536
    1792
    2048

Máy M4 RAM cao có thể chạy lớn hơn GTX 1660 Super.

Nhưng coarse 2048 vẫn không thay native-resolution edge refinement.


13.7 Model lifecycle trên M4

Mặc định:

- một heavy model active tại một thời điểm;
- cache model chỉ khi RAM đủ;
- release khi memory pressure cao;
- giữ mask/alpha ở memory dạng nhẹ.

Mac RAM thấp:

    sequential mode

Mac RAM cao:

    optional warm-model cache

chỉ bật sau benchmark.


13.8 Core ML

Core ML là hướng tối ưu sau V1.

Không phụ thuộc Core ML cho bản đầu.

Sau khi PyTorch MPS chạy đúng:

- benchmark Core ML conversion;
- so sánh output;
- chỉ dùng nếu chất lượng tương đương.


13.9 MLX

MLX có thể benchmark sau.

Không rewrite V1 sang MLX nếu chưa có lợi ích rõ ràng.

Ưu tiên correctness trước speed.

======================================================================
44. ACCEPTANCE CRITERIA
======================================================================

44.1 Source preservation

PASS nếu:

    output width == source width
    output height == source height
    Source Faithful RGB delta == 0


44.2 Transparency

PASS nếu:

- PNG có alpha thật;
- background transparent đúng.


44.3 Native-resolution editing

PASS nếu:

- user sửa được 1 pixel original;
- zoom không làm sai tọa độ.


44.4 Complex topology

PASS nếu:

- hole quai được giữ;
- gap ngón tay được giữ;
- không tự fill lỗ.


44.5 Edge quality

PASS nếu:

- không global Gaussian blur mask để che lỗi;
- unknown region được refine;
- có intermediate alpha.


44.6 Windows hardware

PASS nếu:

- chạy GTX 1660 Super 6GB + 16GB RAM;
- OOM không crash;
- fallback hoạt động.


44.7 Mac hardware

PASS nếu:

- chạy MacBook Pro M4;
- MPS hoạt động khi support;
- unsupported op fallback an toàn;
- adaptive memory profile hoạt động.


44.8 Offline

PASS nếu:

- sau khi cài model, normal inference không cần paid API/cloud.
